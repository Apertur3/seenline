# Changelog

Format: one heading per version. The anchor lines and the `[Hidden in the original]` block grammar are the output contract; changing them is a new major version.

## 0.1.0 (prepared, not yet released)

First release: the readers, the hidden-content block, the CLI and the stdio MCP server, as listed below. Output contract: anchor lines and the `[Hidden in the original]` grammar as in the pinned reference; with the default hidden=describe the entries under the block give a character count instead of the text (`--hidden text` gives the reference's form).

- CLI and MCP server hardening. `--ocr` and `--verify` give `pdftoppm` and `tesseract` the bytes that were parsed on stdin, never a path, so a file replaced on disk after parsing is not what is rendered (library: the `ocr` and `verify` callbacks get those bytes as a third argument); a file's recognition runs share one deadline, two minutes plus ten seconds per page, on top of the 60 s per run, so a long scan fails with `invalid` instead of running for hours; `pdftoppm` output must be a PNG before it reaches `tesseract`, and a BMP needs a plausible size field and DIB header size, not only `BM`. `--json` objects carry `file`, the input path as given, so a consumer can match them to inputs when some fail; an output file that cannot be written is reported as `<file>: could not write the output: ...`, not as an input error. `plainview mcp --help` prints the usage and exits 0. The MCP server sends every `console` method to stderr so nothing but JSON-RPC reaches stdout.
- PDF: text under 2.25 pt is tiny (it was under 2 pt), so a line drawn at exactly 2 pt, a common hiding size, is listed. Hidden glyphs drawn one per text object, four or more in a row and mostly letters, are one entry with the text they spell, a space where a gap on a baseline is a word space; before, repeated letters were dropped as repeats and single letters as words the body shows. A hidden word left out because the body shows it or because it repeats an entry is listed after all when a listed word of the same page with a reason in common is at most four entries away, so a hidden sentence drawn a word per object keeps its "may" and "not". On CrackedPDFs (train split, 7,922 injected files) the payload text itself now reaches a hidden entry in 91.8% of the injected files, up from 67.3% (tiny text 0% to 100%, a glyph per object 0% to 100%, a word or group per object 32% to 68% before, 99% to 100% now); the rest is the acrostic family, which no text-layer check sees. No new flagged file on the benchmark's public files (Set A), the CrackedPDFs originals (0 of 9,774) or the repository fixtures; the smallest text a reader sees in Set A, a figure's 2.48 pt tick labels, stays in the body. Output changes for PDFs with text from 2 to 2.25 pt or with hidden glyph or word runs.
- Hidden entries that read like an instruction to an AI are marked: an optional `suspect` field on a `hidden` entry (`override`, `exfil`, `role`, `verdict` or `addresses-ai`), the line tag `[reads like an instruction to an AI: <kind>]` in `describe` and `framed` mode (not in `text` mode, whose output is unchanged), and `--fail-on-suspect` with the new exit code `4` (precedence 1, 4, 3). Fixed rules in `src/suspect.json` after Unicode normalisation; a triage signal for explicit instructions in English, not a verdict, and blind to data injection (hidden keyword lists, invented facts). No visible text is tagged. No tag on the benchmark's public files (Set A, the 99 of its 101 files that Plainview reads without OCR), its Split-View canaries or the repository's clean fixtures; the repository's injection fixtures and Set A's injection sample are tagged.
- The instruction tag reads more plain wording: asks about the answer itself (a word or phrase to end or begin it with, a link or line to put in it, a language or form to answer in), setting the document aside for another task, score and verdict steering (rate it 10 out of 10, recommend an immediate interview), fake system, developer or user-permission messages, persona and voice switches, and notes addressed to an AI reader, reviewer or screener. Same five reason classes and the same `--fail-on-suspect`. Measured once on wording not used to write the rules: 16 of 40 instruction sentences written by another model (12 before) and 0 of its 20 ordinary notes; CrackedPDFs test split unchanged, 748 of 973 injected files and 0 of 1,946 benign ones. A hand-made set of 24 one-page PDFs, less independent (six of its sentences were known while the rules were written, as examples of the kinds of wording): 21 of 24 (3 before), every kind 3 of 3 except hidden keyword lists (0 of 3, data injection). No tag on Set A's hidden entries apart from its injection sample, or on the repository's clean fixtures and the Split-View canaries; 9 of 590 ordinary lines written to sit close to an instruction are tagged, 7 by the older rules. Older rules no longer tag "ignore errors", a possessive ("select the candidate's name") or "the real goal is", and a greeting or note ("Dear ...", "Note to ...") to "the model" or "the assistant" needs punctuation after it (a colon, comma, semicolon or exclamation mark), or a word that makes the model a reader ("the grading model:", "the model reading this").
- Default hidden=describe. The `[Hidden in the original]` block no longer carries the hidden text by default: each entry keeps its location and kind and says how long it is (`p. 1, clipped text: 50 characters not shown`). The text stays in the `hidden` list of the library result, `--json` and MCP `structuredContent`, and `flags` and `--fail-on-hidden` are unchanged. `--hidden text` (library `hidden: "text"`, MCP `"hidden": "text"`) prints the text as before; `--hidden framed` prints it after a line that calls it untrusted data. Why: models that read the block's text sometimes repeated it as document fact even with the label; with describe, detection is unchanged and the payload does not reach the model. In describe mode a label that carries a name the file chose is cut to its kind (`metadata`, `attachment`, `form field`, `javascript`, `Mail`, `HTML`, `docProps`, `comments`), any label the readers do not write shows as `hidden content`, and a legacy `.doc` or `.rtf` keeps its converted text readable (only the converted file's own entries are described). This changes the block wording against the previous unreleased state and against the reference goldens, which still pass with `hidden: "text"`.

- CLI and MCP server: opt-in `--verify` (on `plainview mcp` too), and a `verify` callback on `convert()` with the shape of `ocr`. Each PDF page with a text layer is rendered with `pdftoppm`, read by `tesseract`, and compared word by word with the text layer; a page where the image shows other words in the place of text-layer words is listed under `[Hidden in the original]` as `p. N, text differs from page image: X words only in the text layer, Y words only in the page image` (counts only; the body keeps the text layer; recognised text is never output). Without `--verify` no output changes. Same tools, timeouts and failure rules as `--ocr`: a missing program fails the file with `unavailable`, any recogniser failure fails it. Found with the Split-View gaps EG_001 (a false /ToUnicode map) and EG_024 (a Type 3 font whose glyphs draw other letters): both are listed, as canaries and as Corpus B task documents; their text still reaches the body. Not caught: order differences (EG_016 in Corpus B), pages the recogniser cannot read. Not quiet: on the benchmark's public PDFs it lists 24 of 1,409 pages (9 of the 39 files it read) that hide nothing, and none of the control set or the repository fixtures; about 0.5 to 0.9 s for a short page and 2.4 s for a dense one. Offered as an audit mode.
- CLI and MCP server: opt-in OCR. `--ocr` (on `plainview mcp` too) reads images and the PDF pages without a text layer with a local `tesseract`, and `pdftoppm` from poppler for PDF pages; nothing is bundled or downloaded. Each page keeps its anchor and the text goes in the body. `--ocr-lang` sets the tesseract languages (default `eng`). A missing program fails the file with `unavailable` and names what to install, also when only some pages of a PDF need OCR (without `--ocr` those pages keep the marker line); a recogniser error, a timeout (60 s per program run) or output over 32 MiB fails it with `invalid`. Off by default; exit codes unchanged. Library: for a PDF the `ocr` callback now also gets the 1-based page numbers to read, and a `PlainviewError` it throws is passed on instead of becoming `text recognition failed`.
- PDF: a page with a short text layer (under 10 letters, such as a one-line memo) is read as text; only a page that shows no text, or that pictures cover for at least half, still counts as a possible scan (text recognition, or the no-text-layer line). Before, every short page counted, so a one-page memo failed without text recognition. On the benchmark's public PDFs three near-empty pages (a page number and nothing else) lose the no-text-layer line; no other output changes.
- PDF: a new entry kind under `[Hidden in the original]`, `unreadable font`, for text whose letters the file does not define: text in a font that cannot be loaded (listed as `(letters not decodable)`), and text in a composite font with a multi-byte code (not a space) that has no Unicode mapping and no glyph in the font (no /ToUnicode and no font program), where the text layer holds the codes themselves. That text leaves the body. Found with the Split-View canaries EG_019 to EG_023 and EG_025 (font metadata removed). No file in the benchmark's public PDFs (the 39 of 40 files, 1,409 of 1,410 pages, read without OCR), its control set or the repository fixtures is flagged. Not caught, as no static check can: a /ToUnicode map that is consistent but false (EG_001), and a Type 3 font whose glyphs draw other letters than their names say (EG_024).
- PDF: the body follows the order a reader sees where the stored order says something else, and the stored text goes under `[Hidden in the original]` as `reading order`, so the text an extractor would read is visible; the block grammar and the anchor lines are unchanged. Two shapes count: words on one baseline, no further apart than a word space (0.6 em), stored out of left-to-right order; and a grid of separate items (rows more than 2 em apart, three or more down a column) stored a column at a time, on a page with no tight text in columns, which is then read row by row; two items per column (a resume's headings beside their entries) stay as stored. Every other page keeps its stored order: on the benchmark's public PDFs (the 39 of 40 files, 1,409 of 1,410 pages, read without OCR) no page changes and none is flagged. Found with the Split-View canaries EG_015, EG_016 and EG_017. Not caught: words spaced wider than 0.6 em, and a grid on a page that also has text in columns. Known false flag: a page of three or more loose items per column stored a column at a time that a reader takes down the columns is read row by row and listed.
- The `[Hidden in the original]` block lists fewer entries; its grammar is unchanged. It was full on almost every clean public file (benchmark Set A as it was then: 20 of 20 DOCX, 27 of 37 PDF; now 15 of 20 DOCX and 22 of 39 PDF), which made `--fail-on-hidden` useless and cost up to a third of the output tokens. Left out now: entries with no text; an entry whose text the visible body already shows as whole words, or that repeats an earlier line exactly; Office package parts a program writes (relationships, data-store ids, SharePoint form, content-type and event definitions, `app.xml` statistics) and machine values in the rest (dates, numbers, ids, booleans, base64, placeholders such as "untitled"); author, editor, company and manager fields that read as names (up to eight capitalised words, initials or name particles, no digits), also in PDF properties; a meta charset and links without a title in HTML. Visible text is no longer flagged: white Word text on the dark header row of its table style, Web Layout hiding (`webHidden`), PowerPoint shapes that run a little past the slide edge, PDF fills outside a form's bounding box or the clip in force, rotated PDF labels inside their clip. Word field codes no longer reach the body; a field that can carry or fetch content (HYPERLINK, INCLUDETEXT, DDE, an unknown command) is listed as `field code`, one that only numbers, dates or cross-references is not. Every Split-View and repo canary is still flagged. Output changes for most Office files and some PDFs.
- White text on a dark ground (white on it has a WCAG contrast ratio of at least 3) is no longer flagged when the ground is known: a PowerPoint shape, slide, layout or master fill or background (through the theme), an Excel solid cell fill (not on sheets with conditional formats), a PDF fill drawn before the text. Pictures, gradients, patterns (also Excel hatch fills), modified theme colours, see-through and soft-masked fills stay unknown, so white text on them is still flagged. A PDF fill covers text only where one of its subpaths does (winding rule), so a dashed frame, a grid or a connector arrow no longer hides what it surrounds.
- PDF: with no text recognition, a file where only some pages have (almost) no text layer is read instead of refused; each such page keeps its anchor and the line `(no readable text layer on this page; it may be a scan or an image)`. A file where every page needs recognition still fails with `unavailable`; output with a working OCR callback is unchanged.
- HTML: XHTML reads (an `<?xml ...?>` declaration is kept as a comment, `<br/>` closes itself). A CSS rule whose selector is not supported is skipped when its declarations cannot hide text; one that can still fails closed. With a linked stylesheet, which already flags all text, the page's own CSS no longer fails the file.
- Email: mbox exports (a leading `From ` envelope line), header-less MIME parts, a trailing `;` after parameters and a multipart that lost its closing boundary are read as mail readers show them.
- PowerPoint: decks with sections (`p14:sectionLst`) no longer fail; section entries are not slides.
- HTML, email and Office failures name their class of cause (for example `an HTML element has too many attributes`, `unsupported CSS selector in a rule that can hide text`) instead of one generic message, without echoing document content.
- PDF: text outside its clipping path (`clipped`) and text squeezed or stretched past readability by horizontal scaling (`squeezed`) is listed under `[Hidden in the original]` instead of the body. Horizontal scaling now also moves the text position. Found with the Split-View canaries EG09 and EG13. Output changes for PDFs that use these.
- Add the `plainview` CLI with JSON, file output and hidden-content exit codes, and a stdio MCP server with the read-only `convert_file` tool.
- First port of the readers: PDF, Word, PowerPoint, Excel, CSV and TSV, HTML, email, subtitles and image metadata; the hidden-content scan (`plainview/hidden`); `convert()` with an optional injected OCR callback.
