# Changelog

Format: one heading per version. The anchor lines and the `[Hidden in the original]` block grammar are the output contract; changing them is a new major version.

## Unreleased

- PDF: the body follows the order a reader sees where the stored order says something else, and the stored text goes under `[Hidden in the original]` as `reading order`, so the text an extractor would read is visible; the block grammar and the anchor lines are unchanged. Two shapes count: words on one baseline, no further apart than a word space (0.6 em), stored out of left-to-right order; and a grid of separate items (rows more than 2 em apart, three or more down a column) stored a column at a time, on a page with no tight text in columns, which is then read row by row; two items per column (a resume's headings beside their entries) stay as stored. Every other page keeps its stored order: on the benchmark's public PDFs (40 files, 1,410 pages) no page changes and none is flagged. Found with the Split-View canaries EG_015, EG_016 and EG_017. Not caught: words spaced wider than 0.6 em, and a grid on a page that also has text in columns. Known false flag: a page of three or more loose items per column stored a column at a time that a reader takes down the columns is read row by row and listed.
- The `[Hidden in the original]` block lists fewer entries; its grammar is unchanged. It was full on almost every clean public file (benchmark Set A: 20 of 20 DOCX, 27 of 37 PDF), which made `--fail-on-hidden` useless and cost up to a third of the output tokens. Left out now: entries with no text; an entry whose text the visible body already shows as whole words, or that repeats an earlier line exactly; Office package parts a program writes (relationships, data-store ids, SharePoint form, content-type and event definitions, `app.xml` statistics) and machine values in the rest (dates, numbers, ids, booleans, base64, placeholders such as "untitled"); author, editor, company and manager fields that read as names (up to eight capitalised words, initials or name particles, no digits), also in PDF properties; a meta charset and links without a title in HTML. Visible text is no longer flagged: white Word text on the dark header row of its table style, Web Layout hiding (`webHidden`), PowerPoint shapes that run a little past the slide edge, PDF fills outside a form's bounding box or the clip in force, rotated PDF labels inside their clip. Word field codes no longer reach the body; a field that can carry or fetch content (HYPERLINK, INCLUDETEXT, DDE, an unknown command) is listed as `field code`, one that only numbers, dates or cross-references is not. Every Split-View and repo canary is still flagged. Output changes for most Office files and some PDFs.
- White text on a dark ground (white on it has a WCAG contrast ratio of at least 3) is no longer flagged when the ground is known: a PowerPoint shape, slide, layout or master fill or background (through the theme), an Excel solid cell fill (not on sheets with conditional formats), a PDF fill drawn before the text. Pictures, gradients, patterns (also Excel hatch fills), modified theme colours, see-through and soft-masked fills stay unknown, so white text on them is still flagged. A PDF fill covers text only where one of its subpaths does (winding rule), so a dashed frame, a grid or a connector arrow no longer hides what it surrounds.
- PDF: with no text recognition, a file where only some pages have (almost) no text layer is read instead of refused; each such page keeps its anchor and the line `(no readable text layer on this page; it may be a scan or an image)`. A file where every page needs recognition still fails with `unavailable`; output with a working OCR callback is unchanged.
- HTML: XHTML reads (an `<?xml ...?>` declaration is kept as a comment, `<br/>` closes itself). A CSS rule whose selector is not supported is skipped when its declarations cannot hide text; one that can still fails closed. With a linked stylesheet, which already flags all text, the page's own CSS no longer fails the file.
- Email: mbox exports (a leading `From ` envelope line), header-less MIME parts, a trailing `;` after parameters and a multipart that lost its closing boundary are read as mail readers show them.
- PowerPoint: decks with sections (`p14:sectionLst`) no longer fail; section entries are not slides.
- HTML, email and Office failures name their class of cause (for example `an HTML element has too many attributes`, `unsupported CSS selector in a rule that can hide text`) instead of one generic message, without echoing document content.
- PDF: text outside its clipping path (`clipped`) and text squeezed or stretched past readability by horizontal scaling (`squeezed`) is listed under `[Hidden in the original]` instead of the body. Horizontal scaling now also moves the text position. Found with the Split-View canaries EG09 and EG13. Output changes for PDFs that use these.
- Add the `plainview` CLI with JSON, file output and hidden-content exit codes, and a stdio MCP server with the read-only `convert_file` tool.
- First port of the readers: PDF, Word, PowerPoint, Excel, CSV and TSV, HTML, email, subtitles and image metadata; the hidden-content scan (`plainview/hidden`); `convert()` with an optional injected OCR callback.
